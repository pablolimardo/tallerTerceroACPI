Cuando aparece break, el for termina. No procesa más elementos.

¿Por qué funciones?

🏗️
En la maqueta, cada habitación hace el mismo proceso: leer → clasificar → decidir. Sin funciones escribís ese código 4 veces. Con una función lo escribís una vez y lo llamás 4. Menos código, menos errores.
❌ SIN función — repetido
# el mismo bloque, una y otra vez... temp_living = 22.5 if temp_living > 26: print("Living: CALOR") elif temp_living >= 16: print("Living: OK") else: print("Living: FRÍO") temp_cocina = 29.0 if temp_cocina > 26: print("Cocina: CALOR") elif temp_cocina >= 16: print("Cocina: OK") else: print("Cocina: FRÍO")

def analizar(nombre, temp): if temp > 26: print(f"{nombre}: CALOR") elif temp >= 16: print(f"{nombre}: OK") else: print(f"{nombre}: FRÍO") analizar("Living", 22.5) analizar("Cocina", 29.0) analizar("Baño", 18.3)

Objetos (POO)

Hasta acá tenías fichas (diccionarios) y funciones sueltas. La POO junta las dos cosas: un objeto guarda sus datos y sabe qué hacer con ellos. Es como pasar de piezas de LEGO sueltas a un robot armado.

La gran ideaDel plano al objeto real

Una clase es el plano de una habitación: dice qué datos tiene y qué puede hacer. Un objeto es una habitación construida a partir de ese plano. Con un plano construís todas las habitaciones que quieras, cada una con sus propios valores.

📄
Clase y objeto
El plano y la habitación construida
▶
🛠️
El diccionario living guardaba datos, pero las funciones que lo usaban vivían aparte. Con una clase, los datos (atributos) y las acciones (métodos) viven juntos en el mismo objeto.
python# La CLASE es el plano class Habitacion: def __init__(self, nombre, temp, hum): self.nombre = nombre # atributos = datos del objeto self.temp = temp self.hum = hum # Los OBJETOS son habitaciones construidas con ese plano living = Habitacion("Living", 22.5, 65) cocina = Habitacion("Cocina", 31.2, 70) print(living.nombre) # → Living print(cocina.temp) # → 31.2
TérminoQué esEn la maqueta
ClaseEl plano / moldeHabitacion
ObjetoAlgo construido con el planoliving, cocina
AtributoUn dato del objetoself.temp
MétodoUna acción del objetover la próxima card
🎯
__init__ y self
Las dos palabras que confunden a todos
▶
__init__
Es el constructor. Se ejecuta automáticamente cuando creás el objeto. Sirve para darle sus valores iniciales.
self
Es "este objeto en particular". self.temp es la temperatura de esta habitación, no de otra. Siempre es el primer parámetro.
🏷️
Analogía: __init__ es la línea de montaje que arma cada habitación. self es la etiqueta que dice "esta pieza es de ESTA habitación". Sin self, todas las habitaciones compartirían los mismos datos y sería un caos.
pythonclass Habitacion: def __init__(self, nombre, temp, hum): # self.X = X → guarda el dato EN este objeto self.nombre = nombre self.temp = temp self.hum = hum self.ventilador = False # valor por defecto living = Habitacion("Living", 22.5, 65) # Al escribir Habitacion(...), Python llama a __init__ solo, # y le pasa el objeto nuevo como self. Vos no pasás self.
⚡
Métodos
Objetos que saben actuar
▶
🤖
Un método es una función que vive dentro de la clase y trabaja con los datos del objeto. Acá la habitación ya no es una ficha muerta: se clasifica sola y decide sobre su propio ventilador.
pythonclass Habitacion: def __init__(self, nombre, temp, hum): self.nombre = nombre self.temp = temp self.hum = hum self.ventilador = False def estado(self): # método que devuelve algo if self.temp > 30: return "ALARMA" if self.temp > 26: return "CALOR" if self.temp >= 16: return "CONFORT" return "FRÍO" def regular(self): # método que actúa self.ventilador = self.temp > 26 return self.ventilador # Usar los métodos con el punto cocina = Habitacion("Cocina", 31.2, 70) print(cocina.estado()) # → ALARMA cocina.regular() # enciende su ventilador print(cocina.ventilador) # → True
El punto lo dice todo: cocina.estado() se lee "pedile a la cocina su estado". El objeto guarda sus datos y sabe qué hacer con ellos. Eso es encapsulamiento.
🧩
Herencia
Sensores especializados sin repetir código
▶
🌱
La herencia es "un plano que parte de otro plano". SensorDHT22 es un Sensor pero con extras. Escribís lo común una vez y solo agregás lo distinto. Como MMO: todos los planos parten de una base y cada uno agrega lo suyo.
pythonclass Sensor: def __init__(self, pin, zona): self.pin = pin self.zona = zona def leer(self): return 0 # genérico # DHT22 HEREDA de Sensor (Sensor entre paréntesis) class SensorDHT22(Sensor): def __init__(self, pin, zona): super().__init__(pin, zona) # reusa el init del padre self.tipo = "DHT22" def leer(self): # redefine el método return {"temp": 22.5, "hum": 65} s = SensorDHT22(4, "Living") print(s.zona) # → Living (heredado de Sensor) print(s.leer()) # → {'temp': 22.5, 'hum': 65}
💡 super() es "el plano padre". Lo usás para no reescribir lo que ya estaba resuelto arriba.
🎭
Polimorfismo
Mismo mensaje, respuesta distinta
▶
📱
Polimorfismo = "muchas formas". Le pedís .leer() a cualquier sensor y cada uno responde a su manera. El programa principal no necesita saber qué tipo es: solo pide, y cada objeto sabe cómo contestar.
pythonclass SensorTemp(Sensor): def leer(self): return "22.5 °C" class SensorNivel(Sensor): def leer(self): return "80 % del tanque" # Mismo bucle, distintos objetos → cada uno responde diferente sensores = [SensorTemp(4,"Living"), SensorNivel(5,"Tanque")] for s in sensores: print(f"{s.zona}: {s.leer()}") # Living: 22.5 °C # Tanque: 80 % del tanque

pythonclass Habitacion: def __init__(self, nombre, temp, hum): self.nombre, self.temp, self.hum = nombre, temp, hum def estado(self): if self.temp > 30: return "ALARMA" if self.temp > 26: return "CALOR" if self.temp >= 16: return "CONFORT" return "FRÍO" class Maqueta: def __init__(self): self.habitaciones = [] def agregar(self, hab): self.habitaciones.append(hab) def reporte(self): for h in self.habitaciones: print(f"{h.nombre:<12}| {h.temp:.1f}°C | {h.estado()}") def hay_alarmas(self): return any(h.estado() == "ALARMA" for h in self.habitaciones) # ─── Armar y correr el sistema ─── casa = Maqueta() casa.agregar(Habitacion("Living", 22.5, 65)) casa.agregar(Habitacion("Cocina", 31.2, 70)) casa.reporte() if casa.hay_alarmas(): print("⚠ Sistema en alerta")

Fundamento
Sistemas de control
▶
🔄
Un sistema de control toma una medida real, la compara con un valor deseado (setpoint) y genera una salida hacia un actuador para reducir el error.
ConceptoDefiniciónEn la maqueta

Señal de referenciaEl valor deseado (setpoint)Termostato a 22°C
Lazo abiertoActúa sin medir el resultadoCalefactor 15 min sin revisar

ConexiónEl if/else ES un controlador

El if/elif/else que aprendiste es el controlador ON/OFF. Temperatura supera el umbral → enciende el ventilador. Baja → lo apaga. Es lazo cerrado en software.

ESP32
La plataforma que conecta todo
▶
c++ · esp32// setup() se ejecuta UNA VEZ al encender void setup() { pinMode(2, OUTPUT); // pin 2 = LED integrado Serial.begin(115200); } // loop() se repite PARA SIEMPRE (como while True) void loop() { float temp = dht.readTemperature(); if (temp > 26.0) { digitalWrite(2, HIGH); // enciende LED } else { digitalWrite(2, LOW); // apaga LED } }
💡 El ESP32 habla con los sensores en C++, y nuestra estación Python en la PC procesa los datos y manda órdenes por red o cable. Las dos lógicas (if, while) son idénticas.
